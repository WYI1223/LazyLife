# ADR Topic Map

> Mainline mapping surface for approved themes and published ADR assets.
> This file contains only publish-complete rows promoted from governance replay execution.

## Purpose

This file records approved themes and their mapping to published current rulings and ADR assets.

Current scope:

1. publish stable theme rows that have already passed classification and carrier checks;
2. keep `Current Normative Source`, `Planned ADR`, and `Published ADR` as explicit first-class columns;
3. preserve a clean mainline surface separate from execution-layer working copies;
4. act as the published journey-layer registry inside the active five-layer governance model rather than as a replacement normative source.

## Boundary

1. Candidate themes and unresolved split / merge decisions stay in execution-layer working copies until approved.
2. `PR-0403` may maintain a topic-map working copy under its own execution directory, but this mainline file holds only publish-complete rows.
3. `Published ADR` must reference a real ADR asset in this directory; it may not be overloaded with current-ruling backlinks.
4. `Current Normative Source` must remain explicit and cannot be hidden inside `Notes`.
5. Exclusions, parked themes, and unresolved debates remain visible in execution-layer artifacts, not here.

## Carrier Relationship

This mainline topic map binds three different governance surfaces for the same decision line:

1. `Theme ID` row is the stable registry identity for the line.
2. `Published ADR` is the journey carrier that reconstructs how the line formed and evolved across source documents.
3. `Current Normative Source` is the current-effective carrier that governs present interpretation.

Operationally:

1. a publish-complete theme row should point to both a published ADR and an explicit current normative source;
2. the ADR explains the journey of the line, but does not replace the ruling as normative authority;
3. later document replays normally append evidence to the existing ADR carrier when the stable why-question remains unchanged;
4. a new theme row is created only when active playbook classification cannot place the nodes into any existing stable line.

## Theme ID Policy

`Theme ID` is a stable governance identifier, not a display-order counter.

Rules:

1. `TH-*` IDs are append-only once referenced by execution records, ADRs, or rulings.
2. Gaps are allowed and must not be auto-filled for cosmetic continuity.
3. A missing ID does not imply a pending mainline row.
4. New theme IDs may be allocated only during playbook `05 DN classification to decision line`, when the active document's nodes cannot be classified into any existing stable line.
5. New IDs use `max(existing TH id in mainline topic-map and active working copy) + 1`.
6. Historical gaps remain reserved history; they are not backfilled into this published registry.

## Row Admission Rule

Only approved themes may be added as rows in this file.

Before a row is admitted:

1. the decision line must have passed the relevant classification and carrier checks and must already be recognized as a stable why-question with an independently traceable decision line;
2. `Current Normative Source` must contain an explicit backlink to the current-effective normative carrier;
3. `Planned ADR` must at least reach a stable placeholder or real filename state;
4. `Published ADR` must reference a real ADR asset in `docs/architecture/adr/`;
5. supersede / redirect edges must remain explicit instead of being implied by row deletion.
