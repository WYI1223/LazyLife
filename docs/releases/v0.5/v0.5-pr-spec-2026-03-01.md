# v0.5 PR Spec (2026-03-01)

## 0. Baseline

v0.5 处理以下两类内容：

1. rulings/modules 中明确标注 `v0.5+` 或在 v0.4 明确延期的项；
2. DI-0~DI-5 中已记录但未进入 v0.3/v0.4 的开放设计项。

## 1. Objectives

1. 承接 v0.4 延期项：完成 S6 真实同步运行时与 S7 提醒规则增强闭环。
2. 完成 R12/R13/R14 的高级能力收口。
3. 形成多编辑范式下可证明的一致性与恢复模型，并以性能与回归门禁压住复杂度。

## 2. Scope Definition

### Must Have

- S6：`SyncOrchestratorService + ExternalMappingRepository + Google OAuth + pull/push`
- S7：RRULE + 提醒提前量配置（含启动恢复）
- R12：P2 元素（`atom_embed/group`）与 Spatial/Canvas 深度联动
- R12：统一 block tree 是否采用的结论与落地路线（评估后执行）
- R13：4 个开放设计项闭合（实现或有约束延期）
- R14：reconciliation 强化（匹配、orphan、超时与回退）
- DI-4：LRU(N) 渲染缓存 + 资源生命周期策略落地
- DI-5：Undo/Redo 基础能力落地
- S6：多 provider 冲突体验统一

### Conditional

- 若 v0.4 未完成 S5 bridge，则 v0.5 升级为 Must Have

## 4. Gate Design

### Gate A: Sync + Reminder Baseline

在 `PR-0503` 后：

- provider pull/push 均可走通
- `external_mappings` 生命周期可追踪
- OAuth 失败与重试路径可回归
- RRULE 与 offset 在启动恢复后仍正确调度

### Gate B: Model Convergence

在 `PR-0507` 后：

- block/content/overlay 三层关系无歧义
- 文本与 block 模式切换不发生静默数据丢失
- reconciliation 与 orphan 路径可诊断、可回归

### Gate C: Runtime Stability + Workflow Completeness

在 `PR-0511` 后：

- 多 pane 长会话下无明显卡顿回归
- LRU 策略下切换延迟与内存占用在目标阈值内
- Undo/Redo、恢复、冲突处理三条链路可联合验收
- schema 升级可回退、可恢复、可诊断
