- Status: Pending

## 背景

仓库中存在两类不应被 git 追踪的大型文件，占仓库 pack 体积的 ~98%：

| 类别 | 路径 | 大小 | 文件数 | 引入时间 |
|------|------|------|--------|----------|
| 项目创世纪 .docx | `docs/init/*.docx` | 14 MB | 5 | 首次 commit (`827c3c2`) |
| 架构基线工具产出 | `docs/reports/v0.2.5/architecture-baseline/artifacts/` | 25 MB | 31 | v0.2.5 PR-0254B |
| **合计** | | **39 MB** | **36** | |

仓库 pack 总计 ~40 MB，清洗后预计 < 1 MB。

这些文件的共同特征：**可复现**（.docx 是原始规划文档的副本，artifacts 可通过 `tools/analysis/` 脚本重新生成）或**不属于源代码**。


## Step 5: git filter-repo 历史清洗

```bash
git filter-repo --invert-paths \
  --path-glob 'docs/init/*.docx' \
  --path 'docs/reports/v0.2.5/architecture-baseline/artifacts/' \
  --force
```

说明：
- `--invert-paths` = 从所有历史 commit 中移除匹配的路径
- `--force` = 允许在有 remote 的仓库中执行
- 磁盘上的文件**不会被删除**，只是从 git 历史中移除
- 操作完成后 remote 会被移除（filter-repo 安全措施），需要手动重新添加

## 注意事项

1. **不可逆操作**：`git filter-repo` 改写了所有受影响的 commit hash。所有基于旧 hash 的引用（issue 评论、PR 链接）将失效。
2. **协作者影响**：所有协作者需要重新 clone 或 `git fetch --all && git reset --hard origin/main`。当前为单人仓库，影响可控。
3. **CI 缓存**：GitHub Actions 缓存可能引用旧 hash，首次 CI 运行可能较慢。
4. **artifacts 重建**：如果未来需要 v0.2.5 baseline artifacts，运行 `tools/analysis/run_architecture_baseline.ps1` 和 `tools/analysis/run_frontend_baseline.ps1` 重新生成。
5. **PR-RB-00 联动**：`docs_link_allowlist.yaml`（T11）需包含 `docs/reports/**/artifacts/` 路径豁免，因为 baseline report .md 中仍引用这些 artifacts。
