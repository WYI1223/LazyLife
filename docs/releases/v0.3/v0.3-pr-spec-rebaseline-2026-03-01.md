## 2. 重排原则
1. 先闭合语义和数据契约（S8/S1/S4/S7），再做编辑器基础设施（S2/DI）。
2. 所有跨 feature 基础设施一律提升到 `lib/core/`（S9）。
3. v0.3 只承诺本地工作流闭环；外部 provider runtime 单独风险管理。
4. 每个 PR 必须可独立回归，不引入“必须一次性大爆炸合并”路径。

## 5. Gate 设计
### Gate A（语义与契约）
在 `PR-RB-05` 后必须满足：

- 手写业务代码中不再依赖 `NoteItem`（生成绑定文件除外）
- 所有创建入口都可观察到对应 `atom_ref`
- Tasks/Calendar 页面不再承担提醒调度入口

### Gate B（编辑器基础设施）
在 `PR-RB-09` 后必须满足：

- 交付里程碑 M1（`PR-RB-06`）：多 pane split/close/resize 可用（支持不同 atom 并行查看）
- 交付里程碑 M2（`PR-RB-08`）：同一 Atom 跨 pane 编辑可用（实时同步、光标独立）
- DI-0：命名冲突消除（`NoteTabStrip` / `EditorGroupModel`）
- DI-1/2：group 生命周期、最后一个 pane 不消失（paneCount ≥ 1）、递归布局不变式成立
- DI-3：布局重启恢复与损坏 fallback 成立
- DI-4/5：跨 pane 内容实时一致、`_rev` 防陈旧、光标独立、无额外冲突机制
