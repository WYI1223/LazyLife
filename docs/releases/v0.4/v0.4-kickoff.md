## 3. 范围演变识别

Kickoff 审计识别出两条在原始 spec 中未被预见的主要工作流，以及一条新发现的 bug 修复工作流。

### 3.1 新增工作流 A — Governance Execution（PR-0400 ~ PR-0406）

**来源**：DI-19/DI-20 在 v0.3 期间已产出完整治理方案并生成 `governance-kickoff-prep/` 目录下的 PR-GOV-00 ~ PR-GOV-06 草案。这些草案在 v0.3 kickoff 时未纳入原始 spec（当时尚未完成 DI-19 修订）。

**工作内容**：
- 建立 ADR 治理基础设施（`docs/architecture/adr/` 目录、元数据格式、模板、CI 集成）
- 将现有 rulings（S1-S9）归档至 `rulings-legacy/`，清空 `rulings/` 作为重建起点
- 按主题序列执行历史 ADR 补录（每条 ruling 转化为结构化 ADR 旅程文档）
- CI 重复检测集成（DI-21 产出 PR-0407 → 重编号为 governance 工作流入口）
- 治理模板与 lifecycle playbook 沉淀

**范围决策**：ADR 治理工作量足够独立，不与 feature PRs 并行，形成 v0.4 的第一条独立工作流。原始 spec 中 PR-0400 编号被占用，整个 governance 工作流使用 PR-0400 ~ PR-0406 序列。

### 3.2 新增工作流 B — Workspace Execution（PR-0407 ~ PR-0413）

**来源**：DI-15（Rust 数据模型单根化）、DI-16（Rust service / FFI 合约）、DI-17（Flutter thin-client 收敛）、DI-18（执行计划）在 v0.3 期间已产出四层切分设计，细化程度远超原始 spec 中 3 个 PR 的预期。

**工作内容**：
- Migration 0012：`workspaces` 表 + `designated_folders` 映射 + DB 触发器（PR-0408）
- Scoped Query Repository：DI-12 系统节点作用域约束（PR-0409）
- Tree Service + Creation Service 单根化（PR-0410）
- Guard FFI：防回归接口守护（PR-0411）
- Flutter Core 层收敛：WorkspaceTreeService 对齐（PR-0412）
- Flutter Features 层收敛：Explorer + Tasks/Calendar 面板同源分组（PR-0413）

**与原始 spec 的关系**：原始 PR-0400 ~ PR-0402 被完整替换为该工作流。新编号从 PR-0407 开始（前 7 个编号已被 governance 工作流占用）。

### 3.3 新增工作流 C — Issue Fixes（PR-0421 ~ PR-0423）

**来源**：v0.3 完成时积压了 7 个已知 bug 和体验问题（issue #47 ~ #53），其中 4 个归入 PR-0421（编辑器 pane 问题）、PR-0422（FFI test 隔离）、PR-0423（跨功能刷新）。

**工作内容**：
- PR-0421：编辑器 4 项修复（#50 overflow、#49 cursor、#48 scroll、#47 tab switch FFI 优化）
- PR-0422：FFI test DB 隔离（issue #46，`%TEMP%` 持久化 DB 跨测试积累）
- PR-0423：跨功能刷新机制（创建/更新事件后 Tasks/Calendar 面板未同步刷新）

**特性**：三个 PR 均无相互依赖，可在 workspace execution 完成后独立并行执行，也可在 governance 执行期间并行推进。

## 7. 风险台账

### R1：Governance 工作流串行链路对 Feature PR 的阻塞

- **现状**：PR-0406 是 PR-0407 的前置，而 PR-0407 是整个 workspace execution 的起点
- **风险**：如果 governance 工作流执行缓慢，将阻塞所有 feature 开发
- **概率**：MEDIUM（ADR 历史补录质量要求高，每篇需要回溯原始决策上下文）
- **缓解**：
  1. PR-0407（CI 重复检测）的 dependency 定义为"推荐在 PR-0406 之后"但不设为硬性前置，CI 检测功能可独立执行
  2. PR-0422（FFI test 隔离）无依赖，可在 governance 执行期间立即启动，减少积压
  3. Governance PR-0400 ~ PR-0406 需要设置时间盒

### R2：单根树 Migration 0012 数据回填风险

- **现状**：Migration 0012 需要为现有 atom_ref 数据回填 designated folder 归属
- **风险**：回填逻辑错误导致 workspace 树状态不一致，影响后续 PR-0409 ~ PR-0413 的正确性
- **概率**：MEDIUM
- **缓解**：
  1. PR-0408 spec 要求包含完整回填逻辑的集成测试（全新安装 + 版本升级 + 触发器负测）
  2. PR-0408 执行完成后，PR-0409 的 Gate 包含"现有 atom_ref 全部可通过 designated folder 作用域查询"的验证条件
  3. DB 触发器（`protect_designated_folder_soft_delete` 等）作为运行时保护层

### R3：FFI 接口切换破坏性变更面积

- **现状**：PR-0411 引入 `atom_create` 等统一接口，PR-0413 移除旧函数，Flutter 消费方需全量迁移
- **风险**：大面积 Flutter 编译错误影响开发节奏；`flutter test` 中 mock 构造需全量更新
- **概率**：MEDIUM
- **缓解**：
  1. PR-0411 保留旧接口兼容壳（仅委托调用，不保留独立逻辑），兼容壳在 PR-0413 清除
  2. PR-0412（Flutter Core）在兼容壳存在时完成核心消费方迁移
  3. PR-0413 清除兼容壳时 `flutter test` 必须全绿才允许合入

### R4：20QA.MD Q9（Reconciliation 宿主 Rust）实现风险

- **现状**：overlay reconciliation 裁定在 Rust 端实现，需要 markdown AST 解析能力
- **风险**：Rust 端 markdown 解析工作量高于预期，PR-0416 可能推迟
- **概率**：LOW（PR-0416 的 v0.4 版本为"基础协议"，reconciliation 算法强化推迟至 v0.5）
- **缓解**：PR-0416 的 AC 明确定义为基础 overlay 读写（`content_rev` 比较 + stale 标记），**不包含** full reconciliation 算法；算法推迟至 v0.5 R14 强化阶段

### R5：Canvas / Conversation / Spatial 延期评估的技术债

- **现状**：三项推迟至 v0.5，但 v0.4 需要完成技术选型研讨
- **风险**：如果技术选型研讨不充分，v0.5 启动时仍面临相同阻塞
- **概率**：MEDIUM
- **缓解**：
  1. Canvas 技术选型以 DI 形式推进，输出"v0.5 Canvas spec 的 canonical input"，不产出 PR
  2. Claude Code SDK 集成验证作为轻量 PoC，评估 Conversation 上限
  3. DI 产出必须明确回答 20QA.MD Q12-Q20 的剩余未决问题（Q13 canvas preview_image、Q18 三视图状态归属、Q19/Q20 Spatial 算法）
