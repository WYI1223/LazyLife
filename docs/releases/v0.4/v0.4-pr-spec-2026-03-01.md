## 1. Objectives

1. 完成 v0.3 已确认延期的能力（尤其 S1 R9-R14 与 S6 真实 runtime）。
2. 将 editor/workspace/reminders 的模块占位能力推进到可发布状态。
3. 在不破坏 v0.3 基础设施（EditorShellService + GroupLayout + EditBuffer）的前提下扩展能力面。

## 2. Scope Definition

### Must Have

- S6：`SyncOrchestratorService + ExternalMappingRepository + Google OAuth + pull/push`
- S1：R9/R10/R11/R14
- S1：R12（Canvas P0/P1 + Spatial Workspace）
- S1：R13（Conversation MVP）
- S3：Phase B + 三视图模式（Tree/List/Spatial）
- S7：RRULE 与提醒提前量配置
- Modules：`EditorResolver.viewMode`、`EditBuffer` op 通道首版

### Conditional Lane

- S5：third-party runtime bridge（仅当真实插件需求触发）

### Deferred to v0.5

- R12 P2（`atom_embed/group`）与统一 block tree 评估/落地
- R13 四项开放设计（跨 Atom 上下文、AI 生成 Atom、长对话增长、扩展集成）
- R14 reconciliation 算法强化与 orphan UX 完整化

## 4. Gate Design

### Gate A: Sync Runtime

在 `PR-0402` 后：

- provider pull/push 均可走通
- `external_mappings` 生命周期可追踪
- OAuth 失败与重试路径可回归

### Gate B: Multi-Content Editor

在 `PR-0408` 后：

- `markdown` / `canvas` / `conversation` 至少 3 类内容可打开与编辑
- `viewMode` 切换不破坏 `Atom.content`
- `atom_overlays` 与 `content_rev` stale 判定生效

### Gate C: Workspace + Reminder

在 `PR-0410` 后：

- Tree/List/Spatial 三模式一致性通过
- RRULE 与 offset 在启动恢复后仍正确调度
