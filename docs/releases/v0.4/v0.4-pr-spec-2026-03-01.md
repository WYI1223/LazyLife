### Semantic Baseline Addendum（DI-11 + DI-12）

#### A. 统一创建入口

1. 规范入口：`atom_create(request)`。
2. `note_create`、`entry_create_note`、`entry_create_task`、`entry_schedule` 在 v0.4 仅保留兼容壳，不再承载独立创建逻辑。
3. 创建事务必须统一为：`insert atom` + `insert atom_ref`（同事务）。

#### B. Pending 语义统一（同源 + 分组）

1. `Tasks` 面板数据源 = `Tasks` 系统文件夹子树内全部 active `atom_ref`；`Pending/Inbox` 仅是 UI 分组。
2. `Calendar` 面板数据源 = `Calendar` 系统文件夹子树内全部 active `atom_ref`；`Pending` 仅是 UI 分组。
3. `Tasks Pending`（组定义）建议：

```sql
task_status IS NOT NULL
AND task_status NOT IN ('done', 'cancelled')
AND start_at IS NULL
AND end_at IS NULL
```

4. `Calendar Pending`（组定义）建议：

```sql
start_at IS NULL
AND end_at IS NULL
```

5. `Tasks Archive`（若显式化）建议：

```sql
task_status IN ('done', 'cancelled')
```

#### C. `in_calendar_designated_scope`（v0.4 收敛实现）

1. 口径收敛：基于 `Calendar` 系统文件夹子树成员资格推导，不再依赖可变映射配置。
2. 由于 DI-12 规定 `Calendar` 系统文件夹必须存在，不再存在“designated folder 未配置”的运行态分支。
3. `parent_node_id` 只表达组织路径，不参与 task/event 语义推导（保持 S4 视图-文件夹正交）。

#### D. DI-12 树与系统节点约束

1. 引入隐藏 `ROOT`，业务节点不再以 `parent_uuid IS NULL` 作为常态。
2. 系统节点 `Inbox/Tasks/Calendar` 必须存在且不可删除，可移动、可重命名（角色与 UUID 不变）。
3. 创建路由优先级固定：显式 `parent_node_id` > 语义意图上下文（task/calendar）> `Inbox` 兜底。
4. 产品语义中的“重新指定映射”在实现上统一为“移动同一系统文件夹节点”。

## 4. Gate Design

### Gate 0: Atom + Workspace Contract

在 `PR-0402` 后：

- 业务创建入口统一走 `atom_create`，旧入口仅兼容委托
- 单根树与系统节点（`ROOT`/`Inbox`/`Tasks`/`Calendar`）约束生效且有回归测试
- Explorer 与 Tasks/Calendar 面板基于同源 `atom_ref` 路径，Tree/Spatial 结果可追踪

### Gate A: Multi-Content Editor

在 `PR-0408` 后：

- `markdown` / `canvas` / `conversation` 至少 3 类内容可打开与编辑
- `viewMode` 切换不破坏 `Atom.content`
- `atom_overlays` 与 `content_rev` stale 判定生效

### Gate B: Workspace Consistency

在 `PR-0409` 后：

- Tree/List/Spatial 三模式一致性通过
- Tasks/Calendar Pending 属于 UI 分组，不再形成独立数据源分叉
