### Semantic Baseline Addendum（DI-11）

#### A. 统一创建入口

1. 规范入口：`atom_create(request)`。
2. `note_create`、`entry_create_note`、`entry_create_task`、`entry_schedule` 在 v0.4 仅保留兼容壳，不再承载独立创建逻辑。
3. 创建事务必须统一为：`insert atom` + `insert atom_ref`（同事务）。

#### B. Pending 语义统一

1. `Tasks Pending`（当前 UI 可映射为 Inbox）：

```sql
task_status IS NOT NULL
AND task_status NOT IN ('done', 'cancelled')
AND start_at IS NULL
AND end_at IS NULL
```

2. `Calendar Pending`（待排期池）：

```sql
in_calendar_designated_scope = true
AND start_at IS NULL
AND end_at IS NULL
```

3. `Tasks Archive`（若显式化）建议定义：

```sql
task_status IN ('done', 'cancelled')
```

#### C. `in_calendar_designated_scope`（v0.4 建议实现）

1. 当 Calendar designated folder 已配置：  
`exists active atom_ref` 且其祖先链包含该 designated folder。
2. 当 Calendar designated folder 未配置：  
Pending 面板仍存在，但显示 empty state + 引导配置 designated folder（避免根级别语义污染）。
3. `parent_node_id` 只表达组织路径，不参与 task/event 语义推导（保持 S4 视图-文件夹正交）。

## 4. Gate Design

### Gate 0: Atom API Contract

在 `PR-0400` 后：

- 业务创建入口统一走 `atom_create`，旧入口仅兼容委托
- `Tasks Pending` 与 `Calendar Pending` 查询口径已固化并有测试
- Explorer 路径（`atom_ref`）与 Pending 可见性关系可追踪

### Gate A: Sync Runtime

在 `PR-0402` 后：

- provider pull/push 均可走通
- `external_mappings` 生命周期可追踪
- OAuth 失败与重试路径可回归

### Gate B: Multi-Content Editor

在 `PR-0408` 后：

- `markdown` / `canvas` / `conversation` 至少 3 类内容可打开与编辑
- `viewMode` 切换不破坏 `Atom.content`
- `atom_overlays` 与 `content_rev` stale 判定生效

### Gate C: Workspace + Reminder

在 `PR-0410` 后：

- Tree/List/Spatial 三模式一致性通过
- RRULE 与 offset 在启动恢复后仍正确调度
