# PR-0411 Guarded FFI Implementation Plan

> **For agentic workers:** REQUIRED: Use superpowers:subagent-driven-development (if subagents available) or superpowers:executing-plans to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Land guarded FFI exports on top of the `PR-0408` to `PR-0410` Rust Core contracts, keep legacy FFI entrypoints as thin expand-stage wrappers, and leave downstream Flutter PRs with a stable caller contract and explicit cleanup handoff.

**Architecture:** Add a dedicated guard layer in Rust Core (`CallerContext`, `AccessGuard`, `Guarded*Service` facades), then route new FFI exports and legacy wrappers through those facades from `crates/lazynote_ffi/src/api.rs`. The default runtime path stays on `NoopGuard`, while tests use `DenyGuard` to prove refusal/error mapping and legacy-wrapper parity tests to prove expand-stage compatibility.

**Tech Stack:** Rust, `rusqlite`, Flutter Rust Bridge, Dart/Flutter bindings regen, Markdown governance/spec docs
